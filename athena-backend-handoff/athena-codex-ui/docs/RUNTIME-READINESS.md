# Runtime readiness and implementation report

This report describes the supplied Athena source and its optional host contracts. The existing composer, model picker, geometric agent marks, workflow, inline execution records, artifact views, Knowledge, settings, resize controls, and keyboard behavior are reused.

**The supplied preview has no initialized Pi provider, Athena TaskManager, connection service, document storage service, PDF exporter, or extraction service.** The adapters call those services only when the embedding application supplies them. A capability, a locally saved preference, a displayed PDF, or a passed fixture test is not evidence of a successful live connection, durable write, or completed analysis.

## Runtime ownership and activation

The preview has three distinct states:

- **UI preview:** authored references can be inspected; no backend or scheduler starts on page load.
- **Development examples:** explicitly enabled under **Settings → About & diagnostics → Development examples**. Timed scenarios and preview response streams use authored data.
- **Runtime:** an explicitly attached Pi connection and/or TaskManager supplies actual state. A Pi session can display real tool/message activity without supplying a task graph, project database, or artifacts. Those missing services remain explicitly unavailable.

TaskManager publishes `revision`, `projectId`, `sessionId`, and a run record, together with tasks, agents, tools, artifacts, events, and approvals. Revisions increase across its subscription, including session changes. Tool IDs, artifact IDs, and artifact versions are passed through navigation; labels and array position are not identity.

A session creation/open receipt confirms metadata only. If the returned activation includes a live Pi connection, the shell attaches it. Otherwise the session can appear with its real ID while the composer reports that its model must be connected. Another session's connected transport cannot silently receive the new session's prompt. The host must coordinate TaskManager state and Pi attachment, publish the correct project/session, and provide historical messages rather than relying on the preview's sample conversation.

Native Pi session creation can be accepted before its new identity is readable. In that case the UI keeps the transition unresolved, preserves the previous draft, and asks for a connection refresh before sending or creating another conversation. If the new ID is confirmed but an optional initial title/model setting fails, the UI reports that the conversation exists and which initialization step failed; it does not claim the whole creation rolled back.

Attachment preparation and submission are bound to the original connection/session generation. A switch or disconnect cannot redirect a prepared message into another conversation. Accepted sends clear only the matching submitted context; newer draft text/files are retained. Unaccepted in-flight content is restored or offered as an unsent message with its attachments, rather than silently replacing a newer draft.

Run model identity is recorded independently of defaults and current picker preferences. A new project/app default affects future resolution; an already started run keeps its reported execution-start model. A snapshot that attempts to replace that model for the same run is treated as a contract error.

## Exact host entry points

These are the public entry points currently exposed by `window.AthenaApp`. They accept existing adapters; the UI does not construct a backend or credentials from an endpoint string.

| API | Purpose and important boundary |
| --- | --- |
| `attachPiSession(sessionOrHostAdapter, options?)` / `detachPiSession()` | Bind a compatible existing session/host adapter and subscribe to its events. The returned detach callback is generation-guarded. Capability detection controls available commands. |
| `attachPiTransport(transport, options?)` | Bind an existing RPC/request transport; defaults to RPC mode unless the options/transport report another mode. Preserve request IDs, response IDs, subscriptions, and extension-response delivery. |
| `attachTaskManager(adapter)` / `detachTaskManager()` | Bind `getSnapshot()` and `subscribe()` plus explicitly advertised lifecycle/command methods from [task-manager.d.ts](../integrations/task-manager.d.ts). Initial snapshot ingestion is asynchronous. |
| `attachConnectionManager(adapter)` / `detachConnectionManager()` | Bind `saveConfig`, `verifyConnection`, and/or `createSession` with optional snapshot methods from [connections.d.ts](../integrations/connections.d.ts). An attached adapter is not automatically marked connected. |
| `attachResearchService(adapter)` / `detachResearchService()` | Bind one [ResearchRecordService](../integrations/research-records.d.ts), or an object with `documents` and `knowledge` adapters. Attaching does not assert that a write/extraction/export succeeded. |
| `createProject(input)` | Forward a capability-gated project creation request to TaskManager. |
| `createResearch(title)` | Request and activate a new conversation through the available TaskManager, ConnectionManager, or Pi session capability. |
| `openResearchSession(sessionId)` | Request opening an actual TaskManager session and activate its returned identifier/connection. |
| `loadDocument(documentId, version?)` | Load/select an existing record version or request that exact document from an attached service. It updates the Manuscript record; use `openWorkspace('manuscript', {documentId, version})` to also open its panel. |
| `ensureDocument(document)` | Seed a project-scoped local document record. This does not persist it to a backend. Evidence uses `{ sourceId, version }`. |
| `openWorkspace(view, selection)` | Navigate to `workflow`, `artifacts`, `timeline`, `knowledge`, or `manuscript`. `execution` is a compatibility route that reveals an existing inline tool. Use `{artifactId, version}`, `{toolId, taskId}`, or `{documentId, version}` as appropriate. |
| `executePi(action, params)` / `refreshPi()` | Invoke a supported Pi action or refresh reported state. Mutating actions are explicit and capability-gated. |
| `respondPiUI(requestKey, response)` | Respond to the exact pending extension request. Cancellation uses `{cancelled:true}`. Prefer the connection/session-qualified request key; the wire response retains the original host ID. |
| `openSettings(category)` / `openPi(section)` / `openModelPicker(kind)` | Open the existing settings workbench or composer picker. Current category IDs are `models`, `execution`, `tools`, `files`, `appearance`, `about`; runtime section IDs remain compatible. |
| `setDemoMode(enabled)` | Enable/disable development examples only while disconnected from real execution. |
| `getState()` / `destroy()` | Inspect the projected UI/connection/record state or unsubscribe/clean up the UI. Destroying the UI is not a substitute for host execution cancellation. |

No example above supplies a fabricated backend response. Implement the relevant adapter in the embedding host, then attach that actual instance.

## Input and extension contracts

Prompt limits count JavaScript `String.length`, not model tokens or UTF-8 bytes. The default 262144 limit is a transport/UI guard, not a claim about any provider's context window. There is no automatic chunking or summarization of excess input.

Without a file-reference service, supported images use actual Pi `ImageContent`, subject to reported model image support. Text/code files up to 1 MiB are read intact into the prompt, then the entire combined prompt is validated. This file-size allowance does not override the total prompt limit. Other binaries remain in the draft with an explicit error. A configured native adapter can accept `fileService` and `maxMessageCharacters`; see [PI-HOST-ADAPTER.md](PI-HOST-ADAPTER.md) and the [implementation](../integrations/pi-host-adapter.mjs).

File references contain a host-issued `id`, project scope, name, MIME type, byte size, and optional `versionId`. A display filename or browser path is not an ingestion receipt. The host validates and resolves every reference, returns all resolved IDs and complete context, and rejects unsupported files. A PDF's successful native preview is not a successful extraction receipt.

The pending extension queue has no 20-request retention limit. Pagination changes only the visible window. Responding state prevents duplicate sends; failed sends retain the request. Detached requests permit cancellation only. Native host resolution events can close their matching dialog. If the host is unreachable, the UI cannot manufacture cancellation acknowledgement or persist host work across process exit.

For assistant completion, use stable message IDs whenever possible. The supported companion terminal events belong to one message/turn boundary. Two identical answers on separate boundaries must remain separate messages. Raw model thinking text is not exposed as activity prose; observed phase/progress indicators remain separate from the final answer.

## Storage and version boundaries

| Data | Supplied preview | Connected-host responsibility |
| --- | --- | --- |
| UI preferences and panel widths | Device storage when available; explicit session-only fallback | Optional cross-device preference service |
| Endpoint/default/role preferences | Explicit local save; no credentials and no implied endpoint connection | Durable configuration, verification, confirmed default, configuration ID |
| Current drafts and attached `File` objects | Retained in memory for the relevant UI/session; rejected sends remain recoverable | Durable drafts or uploads if required by the product |
| Knowledge notes and pins | Project-keyed device storage where supported | Shared project persistence and access control |
| Imported source bytes | Session memory and version-matched local previews | Original-byte storage, durable URI, source/version retrieval |
| Document revisions | Immutable text/evidence revisions in session memory; changed revision is unreviewed | Version history, conflict checks, storage receipts and review events |
| PDF exports | Disabled without export capability; original sample remains a separate asset | Exact-version generation and a matching artifact/location receipt |
| Execution and history | Read-only projection plus explicit development fixtures | Scheduling, durable events/history, replay, approvals and cancellation |

Document saving includes `expectedCurrentVersion` for atomic conflict checks. The service may return a server version identifier, but it must return the same submitted text/evidence and correct document/project identity. Existing local revisions are retained. Version-specific reviews cannot be silently inherited by a changed draft. PDF export includes the requested text/evidence and requires a matching document/version/artifact receipt.

TaskManager artifact evidence uses `{id, version}`; research-document evidence uses `{sourceId, version, location?}`. Host adapters must map their identifiers consistently. The UI displays these references; it does not pretend to have a connected historical source-version viewer when one is absent.

Knowledge's extraction state is separate from review and understanding. A ready extraction is accepted only for the matching source version and supplied text. A new source version does not inherit an older version's review. Imported originals are not silently uploaded, and removing a local list item does not claim to delete a host-stored original.

- [connection-manager-test.cjs](../qa/connection-manager-test.cjs): configuration, checking, and creation receipts.
- [research-records-test.cjs](../qa/research-records-test.cjs): revision immutability, exact receipts, failed saves/exports, project isolation, source storage/extraction, and original-file versions.
- [workspace-views-test.cjs](../qa/workspace-views-test.cjs): exact runtime artifacts, no sample fallback, capability gates, full safe text, and current document versus original sample PDF.

Use fresh test output for pass/fail counts; a prior `qa/integration-results.json` or bundle hash does not validate later edits. Build checks verify inclusion and syntax, not CSS rendering.
