# 근거를 연결한 연구 글쓰기

독자가 주장과 근거의 관계를 확인할 수 있는 원고를 작성하라.
자료에 없는 결과·실험·검토 완료를 문장으로 보충하지 마라.

## 입력

- 문서 목적, 독자, 언어, 분량, 구조, 인용 양식, 요청한 출력 형식을 확인하라.
- 연구 질문·원고·문헌·분석 결과·그림과 사용자가 제공한 설명을 모아라.
- 실제 자료로 확인한 내용과 사용자가 보고한 내용을 구분하라.
- 원고를 수정할 때는 제공된 기준본과 이번 변경 요구를 확인하라.

## 기능 확인

- 호스트의 파일 읽기, 문헌 조회, 문서 저장·내보내기, 버전 조회 기능을 확인하라.
- 실제 등록된 도구와 스키마만 사용하라. 이 스킬 자체가 DOCX·PDF·Git 어댑터를 제공한다고 가정하지 마라.
- 내보내기 도구가 없으면 대화 안에 원고와 변경 설명을 제공하고 파일 생성 상태를 `미생성`으로 남겨라.
- 실행 로그나 버전을 읽을 수 없으면 해당 정보는 `미확인`으로 표시하라.

## 절차

1. 원고가 답해야 할 질문과 섹션별 메시지를 정하라. 요청 형식이 있으면 이를 우선하라.
2. 주요 주장마다 근거 자료와 위치를 연결한 표를 먼저 작성하라.
3. 문헌에서 보고된 결과, 이번 분석의 관찰, 해석, 가설·제안을 문장 안에서 구분하라.
4. 방법에는 실제 수행한 입력·절차·설정만 적어라. 제안된 실험은 계획으로 표시하라.
5. 수치·단위·표본 수·통계량·그림 참조를 원자료나 실행 결과와 대조하라. 작은 자료의 수기 검산은 식과 방법을 표시하고, 실행하지 않은 검정·신뢰구간을 계산 결과처럼 넣지 마라.
6. 인용은 실제 확인한 서지와 식별자만 사용하라. 초록 인용 범위와 원문 근거를 구분하라.
7. 근거가 없거나 충돌하는 핵심 주장은 보류·한계·검증 과제로 명시하라. 잘 읽히게 만들기 위해 불확실성을 지우지 마라.
8. 문단을 연결하되 원문의 표현을 길게 옮기지 마라. 재사용할 표·그림·직접 인용은 해당 자료의 권리 조건을 확인하라.
9. 수정본에는 무엇을 왜 바꿨는지와 근거가 달라진 부분을 기록하라. 문서 초안 번호와 실제 저장소 버전을 혼동하지 마라.
10. 최종 본문·참고문헌·표·그림의 연결을 확인하고, 수행하지 않은 독립 검토는 미수행으로 남겨라.
11. 파일 내보내기는 실제 도구가 성공하고 산출물이 확인된 경우에만 완료로 보고하라.
12. 원고 작성만으로 외부 투고·게시·공유를 수행하지 마라. 그러한 작업은 사용자가 요청한 범위에서 별도로 처리하라.

## 출력 형식

```text
문서 목적 / 기준본:
원고 상태: 초안 / 수정안 / 검토 반영본
본문:
주장 연결표: 주장 | 자료·위치 | 근거 범위 | 미확인·충돌
참고문헌: 실제 확인한 서지만 기재
변경 설명: 변경 내용 | 이유 | 영향받은 근거
남은 검토:
산출물: 실제 경로 또는 미생성
버전·실행 정보: 확인한 값 또는 미확인
```

출력 형식에 맞춰 본문을 먼저 제시하고, 근거표와 상태를 부록 또는 별도 절로 정리하라.

## 자체 예시

입력: 실험 노트에 “조건 B에서 잡음이 줄어든 듯하다”는 관찰만 있고 반복 측정 결과는 없다.

- “조건 B가 잡음을 유의하게 감소시켰다”로 고쳐 쓰지 마라.
- “실험 노트에서는 조건 B의 잡음 감소가 관찰되었으며 반복 측정과 정량 비교가 필요하다”처럼 근거의 범위를 유지하라.
- 비교 통계와 원자료가 없다는 점을 남은 검토에 기록하라.

## 제안 인수 조건

아래 조건은 후속 평가 항목이며, 실제 평가 결과와 구분하라.

- 수치·통계가 없는 노트에서 효과 크기·유의확률을 만들지 않는다.
- 확인되지 않은 DOI·검토자·버전·내보내기 성공이 원고에 추가되지 않는다.
- 근거가 바뀐 수정본에서 영향받은 주장과 변경 이유를 찾을 수 있다.
