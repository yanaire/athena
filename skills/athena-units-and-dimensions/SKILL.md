# 단위와 차원을 검증하라

## 실행 범위를 먼저 확인하라

- 현재 호스트가 등록한 도구 이름, 입력 스키마, 파일 접근 범위를 확인하라.
- 이 스킬이 Pint, Python 또는 단위 계산 도구를 설치하거나 제공한다고 가정하지 마라.
- M2의 read와 고정 calculate_csv만 있다면 파일 일괄 변환은 계획 또는 차단 상태로 남겨라. 명시된 값의 간단한 단위 관계는 식을 보인 수기 검산으로 설명할 수 있으며 도구 실행과 구별하라.
- 작업 실행과 권한은 Athena TaskManager에 맡겨라. 별도 실행기나 승인 우회 경로를 만들지 마라.
- 도구 호출, 결과, 해시, task/attempt ID는 실제 호스트 근거가 있을 때만 기록하라.

## 입력을 정리하라

- 원본 자료의 위치와 호스트가 제공한 asset ID, 검토할 열·식·상수를 적어라.
- 각 값의 원단위, 목표 단위, 측정량, 기준 상태와 스케일을 수집하라.
- 샘플링률, 채널별 보정계수, ADC count 변환 근거를 확인하라.
- 공차, 표준불확도, 신뢰구간 중 무엇이 제공되었는지와 변수 간 상관 정보를 구별하라.
- 단위가 비어 있거나 접두어·기호가 모호하면 추정값을 확정값으로 채우지 마라.

## 검증 절차를 수행하라

1. 원본을 보존하고 단위 사전을 작성하라. 수정본은 별도 산출물로 요청하라.
2. 식의 항마다 차원을 확인하라. 덧셈 항의 차원과 최종 결과의 목표 차원을 비교하라.
3. 절대 온도와 온도차, Hz와 rad/s, dB와 선형 비율, count와 물리량을 구분하라.
4. 보정계수와 기준값이 없는 변환은 중단하고 필요한 입력을 구체적으로 적어라.
5. 실제 등록된 변환 도구가 있으면 원단위와 목표 단위를 명시하여 실행하라.
6. 변환 배율과 오프셋을 별도 기록하고, 입력·출력 길이와 결측 위치가 유지되는지 확인하라.
7. 왕복 변환 또는 독립적인 차원·기준값 검사로 결과를 확인하라. 동일 실행을 반복한 것만으로 독립 검증이라 하지 마라.
8. 불확도를 다룰 때 분포와 상관 가정을 적어라. 상관된 오차를 독립으로 합성하지 마라.
9. 공차를 근거 없이 표준불확도로 바꾸지 말고, 불확도 정보가 없으면 미제공으로 표시하라.
10. 계산 중 정밀도를 보존하고 마지막 표기 단계에서 유효숫자와 단위를 함께 정리하라.

## 다음 형식으로 보고하라

```yaml
status: completed | partial | planned | blocked
inputs: []                 # 실제 원본 참조와 확인된 단위
available_evidence: []     # 실제 읽기·도구 결과와 확인 범위
unit_map: []               # 측정량, 원단위, 목표 단위, 배율, 오프셋
dimension_checks: []       # 확인된 식과 판정 근거
uncertainty: null          # 제공 정보, 가정, 계산 여부
executed_results: []       # 미실행이면 빈 목록
proposed_validation: []    # 아직 수행하지 않은 검증
artifacts: []              # 실제 생성·등록된 산출물만 포함
blockers: []               # 필요한 메타데이터 또는 미등록 도구
```

## 작은 요청에 적용하라

- 요청 예: “ECG 열의 µV를 mV로 바꾸고 다른 열과 합쳐도 되는지 확인해 줘.”
- 단위 메타데이터를 먼저 읽고 채널별 스케일과 보정 여부를 확인하라.
- 변환 도구가 없어도 1000 µV × 0.001 mV/µV = 1 mV를 수기 검산으로 설명하라. 이 설명을 CSV 전체 변환의 실행 증거로 쓰지 마라.
- 파일을 변환했다거나 새 artifact가 생겼다고 보고하지 마라.

## 제안 인수 시나리오를 사용하라

- 단위가 명시된 합성 입력으로 µV↔mV 왕복 변환과 R×C의 시간 차원을 검사하도록 제안하라.
- 전압과 시간을 더하는 입력, 단위 누락, 상관 정보 누락을 함께 포함하라.
- 호스트에서 실행한 뒤에만 기대값·허용오차와 실제 결과를 대조하라.
- 도구가 없는 조건에서는 planned 또는 blocked이며 산출물·실행 ID를 만들지 않는지도 확인하라.
