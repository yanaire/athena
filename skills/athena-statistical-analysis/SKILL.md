# 연구 질문에 맞는 통계 분석을 수행하라

## 실행 범위를 확인하라

- 현재 호스트의 분석 도구, 실제 지원 통계량·방법, 입력·출력 스키마를 확인하라.
- M2의 고정 calculate_csv가 반환하는 통계를 넘어 검정·회귀·신뢰구간을 계산했다고 말하지 마라.
- 필요한 분석 도구가 없으면 확인된 기술통계와 제안 분석을 분리하고 partial, planned 또는 blocked로 표시하라.
- 모든 작업과 권한을 Athena TaskManager에 맡기고 독립 스케줄러를 만들지 마라.
- 실행, 수치, p값, 구간, 산출물 ID는 실제 근거 없이 채우지 마라.
- 제공된 작은 자료의 차이·합계·평균은 식을 보여 수기로 확인할 수 있다. 이를 실제 프로그램 실행이나 추론통계 검증과 구별하고, 검정이 없다는 이유로 확인 가능한 기술적 설명까지 생략하지 마라.

## 질문과 입력을 정리하라

- 분석 질문, 목표 모집단, 추정하려는 효과와 주요 결과 변수를 한 문장씩 적어라.
- 독립 관측 단위와 참가자·시료·반복·시간의 계층, 조건 배정을 확인하라.
- 변수 자료형, 단위, 원본 asset, 결측·제외 규칙과 이미 수행한 전처리를 기록하라.
- 원본을 보존하고 전처리 결과와 제외 목록을 별도 버전으로 다루어라.
- 탐색 분석과 사전에 정한 분석을 구분하고, 주요 비교와 추가 비교를 구별하라.
- 표본수는 전체 행 수와 독립 관측 단위 수를 함께 적어라.

## 분석 절차를 수행하라

1. 실제 자료 범위와 품질을 확인하라. 일부 행만 읽었으면 전체 분포를 관찰한 것처럼 설명하지 마라.
2. 질문에 필요한 기술통계와 분포·산점·시간 추세를 먼저 요청하되 등록 도구가 지원할 때만 실행하라.
3. 표준편차, 표준오차, 신뢰구간을 구분하고 정의·단위·분산 계산의 분모·결측 제외 기준을 기록하라.
4. 대응 자료·반복 측정·군집·자기상관을 확인하라. 같은 참가자의 샘플 수를 독립 표본 수로 사용하지 마라.
5. 독립성, 분포, 등분산 등 선택 방법의 가정을 확인하고 자료와 맞지 않으면 대안을 계획하라.
6. 반복 측정 구조가 필요하면 대응 분석·집계·군집 또는 계층 방법을 검토하고 선택 이유를 적어라.
7. 결측과 제외가 결과에 미칠 영향을 기록하라. 근거 없이 자동 대체하거나 유리한 이상치 제거 규칙을 선택하지 마라.
8. 주요 효과 크기와 불확도를 우선 보고하라. 구간·검정을 실행하지 못했으면 미계산으로 표시하라.
9. 여러 비교를 하면 비교 집합과 보정 방식을 정하라. 탐색 후 고른 분석을 사전 계획이라고 쓰지 마라.
10. 예측 과제는 참가자·시간 단위 분할과 누수를 점검하고 대체·정규화를 학습 자료에만 적합하라.
11. 실제 등록 도구로 실행한 뒤 반환 통계량, 표본수, 단위, 경고와 실패를 확인하라.
12. 유의하지 않음을 동일함의 증거로 해석하지 말고, 관찰된 연관을 설계 근거 없이 인과효과로 표현하지 마라.
13. 작은 표본과 분석 선택의 영향을 밝히고 추가 검증은 제안으로 표시하라.

## 다음 형식으로 보고하라

```yaml
status: completed | partial | planned | blocked
question: null
estimand: null                  # 추정 대상 효과와 단위
data_scope: null                # 실제 asset, 확인 범위, 결측 처리
sample_structure: null          # 행 수, 독립 단위 수, 대응·군집·시간
analysis_plan: []               # 방법, 가정, 주요·탐색 구분
available_evidence: []          # 제공된 자료·실제 도구 결과; 수기 검산은 방법 표시
executed_results: []            # 통계량, 효과·구간, 단위; 미실행은 없음
observed_checks: []
proposed_validation: []
interpretation: null
limitations: []
```

## 작은 요청에 적용하라

- 요청 예: “같은 참가자들의 필터 적용 전후 RMS가 달라졌는지 봐 줘.”
- 참가자별 대응과 여러 구간의 중첩 여부를 먼저 확인하라.
- 단순 CSV 평균만 얻었다면 그것을 보고하고, 대응 효과·불확도 추정은 미실행 계획으로 남겨라.
- 참가자별 차이와 전체 샘플 평균을 혼동하지 말고 p값이나 신뢰구간을 추측하지 마라.

## 제안 인수 시나리오를 사용하라

- 두 조건을 반복 측정한 합성 자료와 참가자 ID를 제공하는 시나리오를 제안하라.
- 시간 샘플 행을 복제해도 독립 참가자 수가 늘지 않는지 확인하라.
- 지원 도구가 있을 때만 알려진 참가자별 효과를 지정 허용오차로 검증하라.
- 고정 CSV 통계만 있는 조건에서는 검정 결과를 만들지 않고 분석 한계를 명시하는지 확인하라.
