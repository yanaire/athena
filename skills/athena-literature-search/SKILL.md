# 문헌 검색과 후보 선별

사용자의 연구 질문을 재현 가능한 검색과 문헌 목록으로 바꾸어라.
이 스킬은 검색 API나 PDF 도구를 설치하거나 제공하지 않는다.

## 입력

- 연구 질문, 분야, 기간, 언어, 대상·방법·결과 조건을 확인하라.
- 사용자가 준 논문·DOI·검색 결과와 제외 조건을 수집하라.
- 누락된 조건은 합리적인 가정으로 표시하고, 결과가 크게 달라질 때만 질문하라.

## 기능 확인

- 호스트에 실제 등록된 검색·HTTP·파일 읽기 도구와 입력 스키마를 확인하라.
- 공급자, 인증 상태, 페이지 조회 및 원문 획득 능력을 실제 응답으로 구분하라.
- 파일 읽기나 정해진 CSV 처리만 있으면 검색 API 실행을 가정하지 마라.
- 검색 도구가 없으면 제공 자료를 정리하고 실행할 검색식을 제안하라. 상태를 `검색 미실행`으로 남겨라.
- 도구 이름·성공 응답·검색 시각·API 버전을 만들어 내지 마라.

## 절차

1. 질문을 핵심 개념과 동의어로 나누고 포함·제외 기준을 적어라.
2. 이용 가능한 제공자에 맞춰 검색식을 작성하라. 제안한 식과 실제 보낸 식을 구분하라.
3. 실행한 요청의 제공자, 검색식, 필터, 조회 시각, 페이지·cursor, 응답 상태를 기록하라.
4. 반환된 결과 수와 실제 확인한 수를 구분하라. 제한·오류·중단으로 남은 페이지가 있으면 부분 검색으로 표시하라.
5. 실제 받은 DOI·PMID·PMCID 등으로 중복을 정리하라. 제목만 비슷한 연구와 사전 공개본·출판본은 근거 없이 합치지 마라.
6. 제목·초록 선별과 원문 선별을 따로 기록하라. 초록만 읽었다면 방법·수치·제외 기준을 원문에서 확인한 것처럼 쓰지 마라.
7. 원문은 제공된 파일이나 사용 가능한 정식 접근 경로로 확보하라. 무료 열람, 다운로드 허용, 재배포 권리를 구분하라.
8. 인용에 쓸 제목·저자·연도·식별자·URL을 실제 자료와 대조하라. 식별자나 서지가 충돌하면 충돌을 남겨라.
9. 후보마다 관련성, 읽은 범위, 핵심 근거, 제외 이유 또는 다음 확인 작업을 기록하라.
10. 검색 범위와 남은 공백을 함께 보고하라. 일부 제공자·페이지 조사만으로 체계적 검색의 완전성을 주장하지 마라.

## 출력 형식

다음 항목을 채우되, 실제 없는 값은 `미확인`으로 표시하라.

```text
질문 / 포함·제외 기준:
검색 상태: 실행 / 부분 실행 / 미실행
실행 이력: 제공자 | 실제 검색식 | 필터 | 조회 시각 | 페이지 범위 | 응답 상태
후보 목록: 서지 | 실제 식별자·URL | 읽은 범위 | 관련 근거 | 선정·제외 이유
원문·권리 상태:
중복·충돌 처리:
남은 조회와 다음 작업:
```

저장 기능이 있으면 실제 저장 위치를 보고하라. 없으면 대화에 결과를 제공하고 파일 저장 여부를 구분하라.

## 자체 예시

요청: “최근의 웨어러블 EMG 피로 추정 논문을 찾아 비교해 줘.”

- 기간이 없으면 가정한 기간을 명시하고 EMG·wearable·fatigue의 조합을 제안하라.
- 검색 기능이 없으면 `검색 미실행`과 검색식·선별 기준을 제공하라.
- 초록 두 편만 제공받았다면 두 초록의 비교로 범위를 한정하고 논문 수·DOI를 보충해 만들지 마라.

## 제안 인수 조건

아래 조건은 구현·평가 시 확인할 항목이며, 이 파일이 통과를 증명하지 않는다.

- 페이지 일부가 실패한 응답에서 부분 상태와 확인한 범위가 남는다.
- 초록만 제공된 문헌은 원문을 읽은 것으로 표시되지 않는다.
- 도구가 없는 환경에서 허구의 검색 결과·인용·저장 성공을 만들지 않는다.
