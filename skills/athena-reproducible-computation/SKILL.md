# 계산과 재현 근거를 연결하라

## 실행 권한과 기능을 확인하라

- 현재 호스트에 등록된 계산 도구와 입력·출력 스키마, 파일 범위, 취소 기능을 확인하라.
- M2에서는 read와 고정 calculate_csv 범위만 전제하고 범용 Python·셸·패키지 설치를 가정하지 마라.
- 지원 도구가 없으면 실행 계획과 필요한 capability를 기록하고 planned 또는 blocked로 끝내라.
- 실행·시도·동시성·권한은 Athena TaskManager에 맡겨라. 별도 작업 큐나 백그라운드 프로세스를 만들지 마라.
- 스킬은 계산 기능을 설치하지 않는다. 허용된 도구 없이 외부 실행 경로로 우회하지 마라.

## 입력을 확보하라

- 실제 원본 asset 참조와 버전, 계산 목적, 기대 산출물 형식을 적어라.
- 비교 기준, 허용오차, 단위, 난수 사용 여부와 재실행 범위를 실행 전에 정하라.
- 입력 파일의 해시와 환경 정보는 호스트가 제공하거나 등록 도구로 확인한 값만 사용하라.
- 모르는 버전·해시·seed·실행 ID는 null 또는 미확인으로 남겨라.
- 원본 파일과 과거 성공 산출물을 덮어쓰지 마라.

## 재현 절차를 수행하라

1. 계산식·알고리즘·입력 열·전처리·매개변수를 하나의 실행 명세로 정리하라.
2. 선택 도구의 지원 범위와 입력 자료형·단위를 확인하라. CSV 통계 도구를 시뮬레이터로 취급하지 마라.
3. 제공된 환경 정보에서 도구 버전, Python·라이브러리·운영체제·장치·lock 참조를 기록하라.
4. 난수 도구가 seed를 지원하면 지정하고 기록하라. seed 고정만으로 모든 환경에서 동일 결과를 보장하지 마라.
5. TaskManager를 통해 실행하고 실제 task/attempt와 도구 호출 근거를 연결하라.
6. 수락 응답과 실행 완료를 구별하라. 로그, 종료 상태, 실제 반환값을 확인한 뒤 결과를 기록하라.
7. 실패·취소·중단은 해당 상태로 남기고 부분 산출물을 성공 결과로 승격하지 마라.
8. 호스트가 생성·등록한 출력만 artifact로 제시하라. 모델이 적은 경로를 생성 증거로 쓰지 마라.
9. 결과의 스키마·단위·유한값·입력 대응을 확인하고 사전에 정한 수치 기준과 비교하라.
10. 재실행할 수 있으면 동일 명세로 별도 시도를 만들고 결과를 비교하라.
11. 차이가 나면 입력, 환경, 알고리즘, seed, 정밀도, 장치와 허용오차를 차례로 확인하라.
12. 바이트 동일성과 수치 동등성을 구별하라. 그림·메타데이터의 시간표시 차이를 계산 오류로 단정하지 마라.
13. 같은 코드의 반복 실행과 독립적인 기준값 검증을 분리하여 보고하라.

## 다음 형식으로 기록하라

```yaml
status: completed | partial | planned | blocked
input_assets: []              # 실제 참조·버전·확인된 해시
recipe: null                 # 도구, 매개변수, 전처리, 단위, seed
environment: null            # 확인된 버전·장치·lock과 미확인 필드
execution: null              # 실제 task/attempt, 상태, 로그 근거
output_artifacts: []          # 실제 artifact와 제공된 해시
available_evidence: []
observed_validation: []       # 실행한 비교와 허용오차
proposed_validation: []       # 아직 실행하지 않은 비교
reproduction_steps: []
limitations: []
```

## 작은 요청에 적용하라

- 요청 예: “이 CSV 통계를 다시 계산해도 같은 값이 나오는지 확인해 줘.”
- 등록된 calculate_csv가 지원하는 열과 통계 항목을 확인해 명세를 고정하라.
- 별도 두 시도의 실제 결과를 비교하고, 호스트에 없는 환경 hash나 실행 ID를 만들지 마라.
- 한 번만 실행했다면 재현 여부는 미검증이며 두 번째 실행은 제안 검증으로 남겨라.

## 제안 인수 시나리오를 사용하라

- 합성 CSV를 동일 도구·매개변수로 두 번 계산하고 기대 통계와 수치 동등성을 확인하도록 제안하라.
- 입력 값 하나를 바꾼 별도 버전은 이전 결과와 구별해 추적되는지 확인하라.
- 취소 또는 미등록 도구 조건에서 성공 판정과 가짜 출력이 생성되지 않는지 확인하라.
