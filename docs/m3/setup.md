# Athena에서 모델 제공자와 프로필 설정하기

Node.js 24 이상에서 `npm ci`, `npm start`를 실행하고 `http://127.0.0.1:4317`을 연다. 기본 저장소는 `~/.athena/workspace`다. 다른 저장소로 검증할 때는 `ATHENA_DATA_DIR`을 지정하고, 재시작할 때도 같은 값을 사용한다. 이 흐름은 OmO나 별도 Pi CLI 설치를 요구하지 않는다. M2.1 분석 코드를 실행하려면 [Docker와 프로젝트 권한 설정](../m21/setup.md)을 그대로 적용한다.

1. **Settings → Models**에서 제공자를 검색한다. 카탈로그에 모델이 있어도 계정의 추론 권한이 확인된 것은 아니다. 키는 제공자 카드에 입력한다. 클라우드 제공자 카드에 호스트 설정이 필요하다고 나오면 먼저 그 클라우드의 자격 증명·리전 등 필수 설정을 준비한다.
2. **Catalog**에서 제공자와 모델을 고르고 이름과 추론 수준을 설정해 프로필을 저장한다. **Verify**는 선택한 모델의 텍스트 스트리밍과 도구 호출을 별도 요청으로 검사한다. 결과와 확인 시각은 해당 프로필 리비전에 기록된다.
3. 앱 기본값 또는 현재 프로젝트의 기본값으로 저장할 수 있다. 채팅 모델 선택기에서 고르면 현재 대화에만 적용된다. 다음 실행에서 대화 → 프로젝트 → 앱 → 기존 호스트 설정 순서로 선택한다. 이미 시작한 부모와 자식은 당시 모델·추론 수준·리비전을 계속 사용한다.
4. OpenAI 호환 서버는 표시 이름과 `/v1` 등이 포함된 API 기본 URL을 입력해 추가한다. Athena가 `/models`에서 실제 ID를 가져온다. HTTP는 루프백에서만, 그 밖의 주소는 HTTPS와 해당 서버의 키가 필요하다. 요청의 리디렉션을 따라가지 않는다. 로컬 모델 서버는 OpenAI Chat Completions 스트리밍을 지원해야 하며 도구 지원은 **Verify**에서 별도로 확인한다.

### 자격 증명 저장

- **Operator key**: `ATHENA_CREDENTIAL_KEY`에 32바이트 키의 64자리 16진수 표현을 서비스 관리자나 비밀 저장소로 전달한다. 같은 저장소를 열 때는 같은 키가 필요하다. 환경 파일을 커밋하지 않는다.
- **Keychain**: macOS에서는 운영자가 서비스 `Athena provider vault v1`, 계정은 실제 `ATHENA_DATA_DIR` 절대 경로 문자열의 SHA-256으로 등록한 키를 읽는다. 저장 파일에는 자격 증명을 암호화해서 보관한다. 키 값은 Athena가 명령 인자로 전달하지 않는다.
- **Memory**: 키가 없고 기존 암호화 저장소도 없으면 휘발성 모드다. 이 경우 프로필과 이력은 보존되지만 UI에서 입력한 키와 OAuth 세션은 재시작하면 다시 설정해야 한다. 기존 암호화 저장소의 키가 틀리면 호스트가 열기를 중단한다.

OpenAI 키는 OpenAI API 요청에 사용된다. **Continue with ChatGPT**는 별도의 [OpenAI 공식 오픈소스 로그인](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)이다. 인증 브라우저가 Athena 호스트와 같은 컴퓨터에서 루프백 콜백 URL에 접속할 수 있어야 한다. 계정에서 허용하지 않는 모델은 호출에 실패할 수 있다. `openai-codex`에는 Athena가 쓸 수 있는 독립 OAuth 등록이 없어 카탈로그만 제공한다. Claude는 Console API 키 또는 지원하는 클라우드 제공자를 사용한다. [Anthropic 정책](https://code.claude.com/docs/en/legal-and-compliance)에 따라 Claude 구독 OAuth는 노출하지 않는다.

UI 로그아웃은 Athena가 해당 제공자에 저장한 자격 증명을 지운다. 운영자가 호스트에 주입한 환경 자격 증명이나 공급자 계정에서 발급된 토큰까지 철회하지는 않는다. 활성 연구 또는 OAuth가 있으면 해당 연구나 로그인부터 종료해야 자격 증명을 바꿀 수 있다.
