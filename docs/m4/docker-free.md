# M4.1 설계: Docker 분석 실행기 교체 지점

이 문서는 교체 전 설계 기록입니다. 현재 실행기는 [M4.2 실행기 결정](../m42/executor-decision.md)을 참고하세요.

M4는 기존 격리 실행기를 그대로 사용한다. 모델 추론, 자식 위임, 일반 파일 읽기, 고정 CSV 계산, 기록 및 결과 파일 열기는 Docker와 분리되어 있다. 임의의 분석 코드는 Docker CLI와 로컬 데몬, 내장 seccomp 프로필, 고정된 `sha256:` 이미지, 정확한 프로젝트 ID 허용 목록이 모두 준비된 경우에만 실행한다.

## 현재 경계

| 책임 | 현재 구현 | M4.1에서 유지할 동작 |
|---|---|---|
| 권한 및 작업 상태 | `TaskManager`와 `executionProjects()` (`runtime/manager.ts`, `runtime/orchestration.ts`) | 부모·자식 권한 분리, 프로젝트 ID 기준 옵트인, 취소·재시작 상태, 호출 및 결과의 실행 ID 연결 |
| 입력 및 출력 | `AnalysisFiles` (`runtime/analysis-files.ts`) | 소스와 입력의 크기·개수·이름 검사 및 바이트 스냅샷, 선언된 출력만 수집, 시도와 연결된 버전 및 SHA-256 무결성, 대화 범위로 다운로드 제한 |
| 대기열 및 수명 | `CsvJobRunner.startAnalysis` / `#runAnalysis` (`runtime/jobs.ts`) | 동시 실행 수, 절대 마감, 제한된 stdout/stderr, 실제 시작·출력·종료 이벤트, 취소 확인 불가 시 추가 실행 차단 |
| 격리 구현 | `analysisAccess` / `runContainer` (`runtime/analysis-container.ts`) | 다른 구현으로 교체할 지점. 현재는 이미지 확인, 읽기 전용 입력, 출력별 파일, seccomp, 자원 제한, PID 1 자체 타임아웃, 컨테이너 제거 확인을 담당 |

## 바꿀 인터페이스

새 실행기는 `probe()`에서 가용 여부, 비가용 사유, 실행기 식별자, Node·Python 버전과 제공 가능한 격리 능력을 반환한다. `run()`은 검증된 불변 소스·입력, 선언된 출력 이름, 구조화된 인수, 제한과 취소 신호만 받는다. 실행 시작과 제한된 출력 이벤트를 내고, 실행 단위가 멈춘 뒤에만 종료 코드·정리 확인 상태·선언된 출력의 제한된 바이트를 돌려준다. 호스트 디렉터리나 파일 권한 정보 자체는 게스트에 넘기지 않는다. 파일 검증·해싱과 최종 게시는 기존 `AnalysisFiles`에 둔다.

먼저 `CsvJobRunner`가 이 인터페이스를 사용하도록 하고 기존 Docker 구현을 첫 어댑터로 감싼다. 현재 `containerId`, 이미지 ID, `/workspace` 등 Docker 고유 값이 들어가는 시도·UI 필드는 구버전 호환 필드로 남긴다. 새 실행기는 `backend`, `executionId`, 검증된 런타임 및 격리 정보로 표현한다. 저장된 Docker 실행을 마이그레이션 과정에서 다시 실행하지 않는다.

## macOS 후보와 교체 조건

Apple Silicon의 Virtualization.framework로 관리하는 Linux 게스트를 우선 평가한다. 네트워크 장치를 만들지 않고, 읽기 전용 런타임 이미지와 좁은 입력·출력 채널만 연결하는 구성을 검증한다. VM 설정과 배포에 필요한 entitlement, 서명, 이미지·인터프리터 라이선스, 시작 비용, 메모리 상한을 먼저 확인해야 한다. WebAssembly/WASI 실행기는 Node/Python 호환성을 별도로 검증한 뒤 제약된 기능의 후보로만 고려한다.

Docker를 빼는 기준은 게스트가 홈 디렉터리·자격 증명·환경·네트워크에 접근할 수 없고, 시간·출력·자원 초과와 앱 강제 종료 뒤에도 실행이 끝나며, 허용되지 않은 출력이 게시되지 않는다는 실실행 증거다. 기존 산출물 다운로드, 취소, 재실행 후 중단 복원도 동일해야 한다. 이 기준을 충족하기 전에는 시스템 Python이나 번들 Node를 분석 코드 실행에 직접 사용하지 않는다. M4에서 후보 구현이나 교체 검증은 수행하지 않았다.
