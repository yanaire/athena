# Sandbox security

Offline analysis uses Wasmtime 50.0.3 and WASI Preview 1. In an idle project, use **Settings → Agents & execution → Project execution → Enable offline analysis**. Permission is off by default and scoped to the selected project. For development, `ATHENA_EXECUTION_PROJECTS` can allow specific project IDs and does not accept a wildcard. A saved project setting takes precedence. Athena refuses to enable analysis if the app-owned runtime is unavailable.

| Tool language | Runtime |
|---|---|
| `python` | CPython 3.15.2 WASI; standard-library CSV, JSON, and statistics. No pip, pandas, NumPy, or native extensions. |
| `node` | QuickJS-ng 0.18.0; file I/O through `qjs:std`. No `std.fs`, Node built-ins, npm, DOM, or `fetch`. |

In a QuickJS `.mjs` script, use `import * as std from 'qjs:std'` and read staged text with `std.loadFile('/workspace/input.txt')`. To write a result, open `/outputs/<name>` with `std.open(path, 'w')`, then call `puts(text)` and `close()` on the returned file. Pass only `<name>` in `run_command.outputs`.

The guest can read approved byte snapshots from `/workspace` and write declared filenames under `/outputs`. It inherits no host environment, network capabilities, shell, or credential store. The sandbox caps WebAssembly linear memory at 192 MiB, each output file at 1 MiB and captured output at 16 KiB per stream. A separate native watchdog samples helper memory every 10 ms and terminates it above 768 MiB, including compilation and host calls. On macOS it checks the larger of physical footprint and resident size; on Linux it checks `/proc/self/status` RSS; on Windows it checks the larger of the process working set and private pagefile usage. Failure to read memory accounting also stops execution.

Startup has a separate 20-second allowance. Once the helper reports readiness, guest execution receives its requested deadline: five seconds by default and at most 30 seconds. Both the native helper and its parent track startup and execution separately, so compilation does not consume the requested guest time. The maximum configured native wall allowance is 50 seconds; the parent monitor has an additional one-second watchdog/reaping grace for each phase. On Unix, the cumulative CPU allowance includes startup and the requested guest budget. A native `SIGXCPU` termination is recorded as a timed-out attempt with confirmed process reaping and no published artifacts.

## Platform enforcement

All supported platforms enforce file growth in the WASI Preview 1 calls themselves: ordinary writes, append writes, positioned writes, truncation and allocation cannot grow a file beyond 1 MiB. The guest descriptor table is capped at 96 entries. A descriptor reused after closing stdin/stdout/stderr is treated as its new file identity; numeric descriptors `0`, `1` and `2` do not exempt reopened files. Actual stdio remains bounded by the parent's capture limits. These boundaries are exercised with real Python/WASI programs in `tests/sandbox-portability.test.ts`.

macOS and Linux also retain native `RLIMIT_CORE`, `RLIMIT_FSIZE`, `RLIMIT_NOFILE` and `RLIMIT_CPU`. Windows has no POSIX `rlimit`; its equivalent guest restrictions are the WASI bounds above, together with the independent memory, total-wall-time and guest-epoch watchdogs. This does not claim an OS Job Object quota. The parent lifetime pipe stops the helper after host loss. Windows cancellation terminates the owned fixed worker handle; it does not signal unrelated processes by stale recorded PIDs.

Published artifacts are checked after successful exit and scratch cleanup. Missing outputs, failed, timed out and cancelled attempts publish no partial artifacts. Each immutable blob is installed from a flushed temporary file. One index rename exposes the entire output batch; caught write or index failures remove the newly installed blobs and preserve the prior namespace. A rollback failure is reported rather than hidden.

The trusted computing base includes the native app and Wasmtime. The helper translates WASM to Pulley bytecode and interprets it. On macOS it runs under Hardened Runtime without permission to generate native executable memory. The native watchdog is sampled enforcement, not an allocation-time OS quota: memory can exceed the threshold between samples, scheduling can delay termination, and Linux RSS excludes swapped pages. It does not limit the Node host or aggregate memory across jobs. Following abrupt host death, a private job scratch directory or unpublished blobs can remain on disk. Index atomicity does not promise filesystem/SQLite atomicity or power-loss durability. Software running under the same OS account may read or modify workspace files, scratch data, and locally writable runtime components; artifact hashes record the bytes published, not protection from another same-account process. Runtime availability checks verify access, not a fresh integrity check before every execution. Protect the application and workspace from untrusted local software.
