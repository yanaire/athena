# M2.1 실행기·호환성 검증

기준은 M2 `d8a9241c790fdd9f2e88de5af5ab9429c2eaf9ea`이다. 아래 검사는 [실모델 UI 인수](acceptance.md)와 판정 기준이 다르다.

| 경로 | 관찰 |
|---|---|
| 구 M2 데이터 → 새 호스트 | 구 호스트에서 Qwen이 위임한 실행 `95f4808f-c810-40cc-aa1b-d38207e0007f`를 종료 후 같은 경로에서 열었다. 부모·자식 세션의 이력 해시와 작업·시도·도구·프로세스의 직렬화 해시가 같았다. 원래 주소에서 받은 `statistics.json`의 평균은 `8`, 크기는 `162`, SHA-256은 `e5757cca20b64f714b6adc044097098057e0267170420b30722807710262bd47`로 동일했다. `scripts/check-m2-upgrade.mjs`로 비교할 수 있다. |
| 통제된 Pi 응답 + 실제 컨테이너 | 자식이 파일과 인자 `5`를 받아 Python을 실행했다. 부모가 검증한 값은 `37`. 호스트를 다시 연 뒤 소스, `result.json`, `note.txt` 다운로드가 이전 바이트·해시와 일치했다. 다른 자식은 명시적으로 받은 산출물만 읽었다. 오류 프로그램은 stdout `out witness`, stderr `err witness`, 종료 코드 `7`과 프로세스 ID를 실제 다음 모델 요청에 전달했다. 자동 재실행은 없었다. |
| 실제 Docker 실행 | Python이 허용된 입력을 읽고 빈 파일과 일반 텍스트를 만들었다. 다음 Node 명령이 그중 텍스트를 읽었다. 변경하지 않은 출력 파일은 게시되지 않았다. 호스트 전용 파일, Docker 소켓 및 외부 TCP 연결은 접근할 수 없었고 지정하지 않은 출력 파일 쓰기도 거부됐다. |
| 종료와 복원 | 별도 세션의 `sleep` 하위 프로세스를 `docker top`으로 확인한 뒤 취소 또는 시간 초과를 발생시켰다. 두 경우에 해당 컨테이너가 사라졌다. 호스트를 `SIGKILL`로 종료한 별도 검사에서도 게스트의 자체 제한 시간이 컨테이너를 종료했다. 중단 시도를 복원해 재제출하면 중복으로 거부했다. |
| 기존 화면 | 데스크톱 1440px와 모바일 390px에서 구 M2 결과 다운로드와 해시를 확인했다. 일반 실행용 UI fixture에서는 Python 소스·CSV·JSON 다운로드를 같은 두 폭에서 검사했다. Fixture는 모델 실행의 증거가 아니다. |

실행 환경은 macOS arm64, Node.js 24.22.3, 로컬 Docker의 Linux 컨테이너였다. 검증한 이미지 ID는 `sha256:cf0f1b9ce95e84000ca4f395d4619ae3318ce4c29038ce0a751c4ee9ab307c4d`다. 다른 컴퓨터에서 다시 빌드하면 ID가 달라질 수 있다. 동일 설정을 만들려면 [실행 안내](setup.md)를 따른다.

`npm run check`와 이미지 ID를 설정한 `node --test --test-concurrency=2 tests/*.test.ts`에서 **50/50 통과, 건너뜀 0**을 확인했다. 앞선 전체 병렬 실행에서는 기존 모델 슬롯 테스트 한 건이 15초 제한을 넘겼다. 그 테스트는 단독으로 0.69초에 통과했으며, 위의 제한된 병렬 실행에서도 통과했다. DOM 통합 테스트 103/103와 계약 테스트 52/52는 별도로 수행했다. 다른 프로젝트가 활성화된 상태에서 빈 프로젝트를 골라 첫 대화를 만드는 동작도 실제 Chrome과 호스트에서 확인했다.
